# Selene Roadmap

An LLM is a function: it takes a sequence of tokens and outputs a probability for every possible next token. Training means adjusting millions of numbers until those probabilities match real text. Everything below is the detail of how that works.

## Stages

Each stage ends with something that runs and that I can check.

- [ ] **1. Gradient descent on a line**
  - Learn: loss, derivatives, learning rate
  - Done when: my program finds slope and `b` from noisy points
- [ ] **2. Scalar autograd engine**

- [ ] **3. Bigram language model**

## Where the languages fit

Learn each concept somewhere comfortable first, then use a new language where it fits naturally. Learning a concept and a language at the same time makes it impossible to tell whether a bug is in the math or the language.

- **Python + NumPy/PyTorch**: trying ideas and plotting loss curves. PyTorch is the **answer key**: run the same small input through PyTorch and through my code, and the numbers should match to about 1e-5.

## Stage 1: the first task (in C)

1. Pick a true line, e.g. `y = 2x + 3`. Generate 100 points with a bit of random noise.
2. Start with a random `slope` and `b`.
3. Write a **loss**: the mean of `(predicted_y - real_y)²` over all points.
4. Work out **on paper** the derivatives of the loss with respect to `slope` and `b`.
5. Loop: `slope -= learning_rate * d_slope; b -= learning_rate * d_b;` and print the loss every N steps.

Questions to answer through experiment:

- What happens with a learning rate of 0.0001? 0.1? 1.0? Why does it sometimes blow up?
- Why square the error instead of using it directly?

# Chapter 2: The Historical Path

Instead of going straight to an LLM, follow the order in which things were invented. Every big idea was invented because the previous one hit a wall. Hitting those walls myself makes the solutions feel obvious instead of arbitrary.

Most of the work is shared between an image classifier and an LLM: neurons, layers, backpropagation, gradient descent, softmax, cross-entropy, train/test splits, optimizers. What is specific to text: tokenization, embeddings, and sequence handling (first recurrent networks, then attention).

History is a guide, not a rule. Modern tools (e.g. the Adam optimizer, 2014) and my own visualizations are welcome at any point.

## Two adjustments

1. **Handwritten digits (MNIST) before clouds.** Public cloud datasets are small (a few thousand photos), they come as JPEG/PNG (decoding them in C is a project of its own), and photos really need convolutional networks, a side branch the LLM path doesn't use. MNIST (1998) has 70,000 handwritten 28×28 grayscale digits in 10 classes, and its file format is simple enough to parse in C in about 20 lines. Clouds can come back later as a graduation project.
2. **Follow the main line of history, not all of it.** Build only what leads to the Transformer. Side branches (SVMs, hidden Markov models, hand-built grammars) can be reading detours.

## The path

- [ ] **1805 / 1847: Least squares, gradient descent** (Legendre, Gauss, Cauchy)
  - Build: fit a line (Chapter 1, stage 1)
- [ ] **1958: Perceptron** (Rosenblatt)
  - Build: one neuron that separates 2D points into two groups. Draw it in SDL, with the line moving as it learns
  - Wall: it can't learn XOR (Minsky & Papert, *Perceptrons*, 1969). The field stalled
- [ ] **1986: Backpropagation** (Rumelhart, Hinton, Williams)
  - Build: scalar autograd engine, then a multi-layer network that solves XOR
  - Wall: scalars are too slow for real data
- [ ] **1998: MNIST classifier** (LeCun et al.)
  - Build: first real classifier (softmax, cross-entropy, batches). Build the tensor library in C here, because it becomes necessary
- [ ] **2003: Neural language model** (Bengio et al.)
  - Build: bigram model, then an MLP language model on characters
  - Wall: `"cat"` and `"kitten"` are unrelated numbers
- [ ] **2013: word2vec** (Mikolov et al.)
  - Build: embeddings that capture meaning (king − man + woman ≈ queen)
  - Wall: fixed context window
- [ ] **1997 / 2014: RNN / LSTM** (Hochreiter & Schmidhuber; Sutskever et al.)
  - Build: a network that reads one token at a time and remembers
  - Wall: slow, and it forgets long contexts
- [ ] **2014 → 2017: Attention, then the Transformer** (Bahdanau et al.; Vaswani et al.)
  - Build: tiny GPT on Shakespeare
  - Wall: characters make sequences too long
- [ ] **2016: BPE** (Sennrich et al.)
  - Build: tokenizer in Rust
- [ ] **2019: GPT-2** (Radford et al.)
  - Build: real training, then the inference engine running the real GPT-2 weights
- [ ] **2020+: Scaling laws, instruction tuning, RLHF**
  - "Maybe everything"
- [ ] **Graduation project: cloud classifier**
